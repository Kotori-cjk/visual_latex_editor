A local, source-backed LaTeX editor. Click text or images in the **actual compiled PDF**, edit the corresponding content, and compile again. No account, frontend build step, or cloud service is required.

一个在本机运行的 LaTeX 可视化编辑器：点选真实 PDF 里的段落和图片，在右侧修改，再重新编译。界面为中文，代码和安装说明可用于独立项目。

![和贝伦卡斯泰露一起编辑吧！](https://github.com/Kotori-cjk/visual_latex_editor/blob/main/docs/140100396_p1.png)

## What you can do

- Select paragraphs, titles, formulas, tables, images and captions from the PDF or the document outline.
- Edit ordinary text without typing LaTeX; inline formulas remain protected.
- Replace a PNG, JPEG or WebP image, change its width/height, and edit its caption.
- Switch to LaTeX for formulas, tables and layout commands, or open the entire source.
- Save changes, undo recent saves, zoom the preview, search content, and inspect compiler errors.
- Download the latest compiled PDF, or export a single `.tex` with its raster images embedded.
- Keep the last successful PDF when a new compilation fails.

**Scope:** this is a block editor, not a Word-style rich-text canvas. Text is selected by source block, formulas and tables are edited as LaTeX, and images are replaced as whole files. PDF hit regions use SyncTeX and are approximate, especially with custom macros; the outline is always available.

## Quick start

Requirements: Python **3.10+**, [Tectonic](https://tectonic-typesetting.github.io/book/latest/installation/), and Poppler's `pdftoppm` on `PATH`.

### One environment for Windows, macOS or Linux

With Conda or Miniforge installed:

```sh
conda create -n visual-latex -c conda-forge python=3.11 tectonic poppler
conda activate visual-latex
git clone https://github.com/Kotori-cjk/visual_latex_editor.git
cd visual_latex_editor
python -m pip install -e .
visual-latex-editor --check
visual-latex-editor --open
```

Tectonic documents its Conda installation, and the [Poppler feedstock](https://github.com/conda-forge/poppler-feedstock) provides packages across these platforms. The first LaTeX build can download its required packages and fonts; later builds use the cache.

### Using existing tools

Install Tectonic and Poppler separately, then create a Python environment:

```sh
python -m venv .venv
# Windows: .venv\Scripts\activate
# macOS/Linux: source .venv/bin/activate
python -m pip install -e .
python -m visual_latex_editor --open
```

If the executables are outside `PATH`, supply them explicitly:

```sh
visual-latex-editor --tectonic /path/to/tectonic --pdftoppm /path/to/pdftoppm --open
```

Or set `VISUAL_LATEX_TECTONIC` and `VISUAL_LATEX_PDFTOPPM`. On Windows use paths to the `.exe` files. After installation, `scripts/start.cmd` or `sh scripts/start.sh` launches the editor. The server remains attached to its terminal; press **Ctrl+C** to stop it.

Open **http://127.0.0.1:8765**. The included tea example loads automatically into an editable copy.

## A small, original example

The starter document is **“一杯茶的冷却记录 / A cup of tea”**: two pages, two original illustrations, a cooling equation and a small table. All numbers are synthetic model outputs. The drawings are generated by `scripts/make_example_images.py`; there are no third-party photos or course materials.

Source: [`src/visual_latex_editor/example/demo.tex`](src/visual_latex_editor/example/demo.tex). [View the compiled example PDF](docs/tea-example.pdf).

Try this workflow:

1. Click a paragraph in the PDF and change the text in the right panel.
2. Click **保存修改 / Save** or press **Ctrl+S**.
3. Select the cup image, choose a replacement, change its size or caption, and save.
4. Click **编译 PDF / Compile PDF** to refresh the actual page layout.
5. Use **下载 PDF / Download PDF** or **导出 .tex / Export .tex**.

Editing the example equation does not recalculate the illustration or table: they are independent document content.

## Your files

By default the project lives under `.visual_latex_editor/` in the directory where you start the application. It is ignored by Git. Use `--project /path/to/my-document` to select another directory; each directory stores one active document.

```text
.visual_latex_editor/
├── report.tex               # current editable source
├── report.previous.tex      # previous saved source
├── assets/                  # starter/replacement images
└── build/<build-id>/         # PDF, preview pages, SyncTeX and logs
```

Saved changes survive restarts. The undo button remembers saves made in the current browser session (up to 25 block saves); it is not a version-control system. Build history is kept on disk. Choose a fresh `--project` directory to start another copy of the example.

### Import / export

Import expects one complete `.tex` with a `document` environment. The easiest portable import is a file previously exported by this editor: it contains ASCII image PDFs in `filecontents*` blocks. A plain source with external image references needs matching files in the project's `assets/` directory, or image replacement through the UI.

Multi-file LaTeX projects, bibliographies, custom packages, arbitrary PDF/vector assets and complex macro-generated layouts are outside the initial supported scope. Exported raster images become JPEGs on white backgrounds; transparency is flattened. Formula/table editing remains available in source mode.

## Configuration

```sh
visual-latex-editor --help
visual-latex-editor --port 8877 --project ./my-document --open
visual-latex-editor --cache /path/to/tectonic-cache
```

The server listens on **127.0.0.1 only**. `--check` reports executable paths without starting a project. Compiling does not update the preview until both LaTeX and PDF rendering succeed; an error leaves the prior PDF intact. A saved version must compile successfully before its PDF can be downloaded.

## Development and tests

```sh
python -m pip install -e .
python -m unittest discover -s tests -v
node --check src/visual_latex_editor/static/app.js
```

Tests cover block parsing, image conversion, source round trips, revision protection, local request checks, image replacement and failed-build recovery. HTTP tests use a temporary project and do not modify your saved document.

To also run the real compiler/renderer integration check:

```sh
python scripts/check_integration.py
```

This needs Tectonic and Poppler on `PATH` (or the two executable environment variables). It compiles the example, edits a paragraph, replaces an image, verifies recovery from a TeX error, and compiles the standalone export in a temporary directory. The GitHub workflow runs unit tests on Windows, macOS and Linux, builds the Python wheel, and runs the real integration check on Linux.

```text
src/visual_latex_editor/server.py    HTTP API, source edits, compilation, SyncTeX mapping
src/visual_latex_editor/static/      HTML/CSS/JavaScript interface
src/visual_latex_editor/example/     original starter document and drawings
tests/                              isolated unit/HTTP tests
scripts/                            launchers, illustration generator, integration check
docs/                               preview and project notes
```
